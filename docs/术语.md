# MicroDuck 复现术语表

> 给第一次接触机器人、嵌入式系统和强化学习的读者使用。本文把专业术语尽量翻译成直白说法。

## 一、工程与机械

### BOM（Bill of Materials，物料清单）
做一台机器人需要的全部零件清单，包括型号、数量和备注。MicroDuck 的 BOM 可能包括舵机、主控、HAT、电池、轴承、螺丝、打印件、线材和调试工具。

### CAD（Computer-Aided Design，计算机辅助设计）
用电脑设计机械零件和装配关系的软件或文件。`microduck-replica-cad` 中的 SolidWorks 文件就是 CAD 资料。

### STL
3D 打印常用的三维模型格式。它通常只描述外形，不包含完整的材料、螺丝、舵机参数和装配关系；能下载 STL 不等于整机一定能装配成功。

### STEP
适合工程交换和继续修改的三维模型格式，相比 STL 通常更容易在 CAD 软件中编辑。

### 装配体
把多个机械零件放在 CAD 软件中，检查孔位、螺丝、轴承、舵盘、线束和运动范围是否互相干涉。

### 版本冻结
在采购和打印前固定仓库 commit、CAD Release、舵机型号、主控板批次和系统版本，避免不同版本零件互相不匹配。

### 复现基线
一台复现机器人采用的唯一标准配置。例如：HD-1910-C001 ×15、Radxa Zero 3W、某个 CAD 版本和某个软件 commit。

### 舵机（Servo）
能够按照指令转到指定角度的小型电机组件，通常包含电机、齿轮、控制电路和位置传感器。

### 执行器（Actuator）
把软件命令变成实际运动的部件。舵机是执行器的一种。

### XL330
Dynamixel 系列智能舵机。官方 MicroDuck 路线主要围绕 Dynamixel 类舵机和相应通信方式构建。

### HD-1910
飞特（Feetech）智能舵机。社区 MicroDuck 复刻常使用 HD-1910-C001 ×15。它不能被当作 XL330 的直接电气和动力学替代品。

### 关节（Joint）
两个机械零件之间可以相对转动的位置，例如髋、膝、踝、颈部和嘴部关节。

### 自由度（DOF）
机构可以独立运动的方向数量。15 个舵机不一定等于策略输出的 15 个动作，因为部分舵机可能负责头部或嘴部。

### 零位 / 中位（Zero Position）
软件和硬件约定的关节标准位置。零位错误会导致机器人站歪、动作方向错误或策略失控。

### 舵机 ID
总线上每颗舵机的唯一编号。两颗舵机使用相同 ID 会产生通信冲突。

### 舵盘（Servo Horn）
安装在舵机输出轴上的圆盘、十字盘或摇臂，用来把旋转传给腿、头等结构件。

### 回差（Backlash）
齿轮和结构存在间隙，舵机换方向时先转了一点但输出端还没有跟着动。回差会造成抖动、漂移和落脚不准。

### 质量、惯量、质心
- **质量：** 零件有多重。
- **惯量：** 零件转动起来有多难。
- **质心：** 重量平均集中的位置。

电池、HAT、线束或舵机位置改变后，机器人重心和运动表现也会改变。

### 运动学（Kinematics）
研究“关节转多少，脚或头会移动到哪里”，主要关注位置和姿态。

### 动力学（Dynamics）
研究“需要多大的力和扭矩才能完成运动”，还要考虑质量、惯量、摩擦和加速度。

## 二、电气与嵌入式

### 主控 / 主控板
运行机器人软件、读取传感器并发送运动指令的计算机。推荐复现方案中使用 Radxa Zero 3W。

### SoC（System on Chip）
把 CPU、内存控制器和各种接口集成到一块芯片中的系统芯片。RK3566 是 Radxa Zero 3W 使用的 SoC。

### HAT（Hardware Attached on Top）
安装在主控板上的扩展板。MicroDuck 的 RPI Robot HAT 用来连接舵机总线、IMU、音频和电源等外设。HAT 不是主控本身。

### IMU（Inertial Measurement Unit，惯性测量单元）
感知机器人倾斜、旋转和加速度的传感器组合，通常包括加速度计和陀螺仪。它是机器人判断姿态的重要来源。

### 加速度计
测量各方向的加速度，也可以利用重力方向估计机器人是否倾斜。

### 陀螺仪
测量机器人绕各个轴旋转的速度。

### IMU 坐标系
规定 IMU 的 X、Y、Z 轴方向和正负方向。仿真和真机的坐标系不一致时，策略可能表现异常。

### 舵机总线
主控和多颗舵机共用的一组通信线路。主控可以通过总线给舵机发指令，也可以读取位置、温度、电压和负载。

### 半双工（Half-duplex）
同一根信号线既能发送也能接收，但同一时刻只能一个方向通信。收发方向控制错误会导致无响应或丢包。

### TTL / RS-485 / RS-232
三种不同的电气通信方式。不能因为插头长得相似就直接互连；必须确认电平、电源、信号线和收发方式。

### UART / 串口
主控和外部设备按顺序传输数据的通信接口，在本项目中可能用于舵机总线和调试。

### 波特率（Baud Rate）
串口通信速度，例如 1 Mbps。主控、转接板和舵机必须使用匹配的波特率。

### `/dev/ttyS2`
Linux 给某个硬件串口分配的设备文件名。如果 `serial-getty` 等登录服务占用它，机器人程序可能无法控制舵机。

### 设备树（Device Tree）
Linux 用来描述开发板硬件、接口和引脚复用的配置。UART、I2C、摄像头能否正常工作常常取决于设备树配置。

### I2C / SPI
主控和传感器、显示器或扩展芯片通信的总线。I2C 线少、适合多个低速设备；SPI 通常更快，但需要更多片选线。

### 电源压降
舵机大电流工作时，电池、线材、接头和保护板造成的电压下降。严重时会导致舵机掉线、主控重启或动作变弱。

### 反灌 / 反向供电
多个电源同时连接时，电流从一个电源倒流进另一个电源。USB、主控、HAT 和舵机电源不能盲目并联。

### UBEC
把较高电压稳定转换为电子设备所需低电压的电源模块。

### 2S 电池
由两节锂电芯串联组成的电池包，标称电压通常约 7.4 V，满电约 8.4 V。实际能否使用要看舵机和电路规格。

## 三、软件与控制

### Runtime（运行时）
真机上持续运行的软件系统，负责读传感器、运行策略、控制舵机并执行安全限制。

### Daemon（守护进程）
在后台长期运行的服务进程。MicroDuck 使用多个 daemon 分别处理机器人、网络、手柄、媒体和更新等功能。

### `robotd`
MicroDuck 中直接拥有机器人电机总线和控制循环的核心服务。把电机控制集中到一个进程，有利于安全和资源管理。

### IPC（进程间通信）
多个软件进程之间交换消息的方法。

### Unix socket
同一台 Linux 设备上不同进程之间通信的接口。MicroDuck 的服务可以用它交换命令和状态。

### JSON-RPC
用 JSON 文本格式调用远程函数的一种协议。例如客户端发送“以某速度前进”，服务端返回执行结果。

### 控制环（Control Loop）
反复执行“读取状态 → 计算动作 → 发送指令”的循环。

### 50 Hz
每秒执行约 50 次控制循环。一个周期约为 20 毫秒。

### 实时性
系统能否在规定时间内稳定完成每一次控制计算。平均速度快还不够，偶发卡顿和延迟抖动同样危险。

### 安全层（Safety Layer）
在动作发送给舵机前检查和限制危险指令的软件层，可能包含角度限位、速度限位、掉线处理、过温保护、急停和安全姿态。

### ONNX
保存和交换神经网络模型的通用格式。训练完成的策略可以导出为 ONNX，再部署到 ARM 主控上。

### ONNX Runtime
加载和运行 ONNX 神经网络模型的软件运行库。

### 推理（Inference）
模型训练完成后，输入当前传感器数据，计算下一步动作。推理不是训练。

## 四、仿真与强化学习

### RL（Reinforcement Learning，强化学习）
让机器人通过“尝试动作 → 获得奖励 → 改进策略”学会行为的方法。

### PPO（Proximal Policy Optimization）
一种常用的强化学习算法，可用于学习站立、速度跟踪和行走。

### Policy（策略）
根据当前状态计算下一步动作的模型。例如输入姿态、关节状态和行走指令，输出关节控制量。

### Observation（观测）
策略在当前时刻能看到的输入数据。MicroDuck 资料中常见“61 维观测”，具体组成和顺序要以目标版本代码为准。

### Action（动作）
策略输出给执行器的控制量。资料中常见“14 维动作”，不一定等于全部 15 个舵机。

### Reward（奖励）
告诉强化学习系统“这一步做得好不好”的分数。站稳、跟踪速度可能得到奖励；摔倒、动作过大可能受到惩罚。

### Episode（回合）
强化学习从开始到结束的一次完整尝试，例如机器人从站立开始直到摔倒或达到设定时间。

### MJCF
MuJoCo 使用的 XML 机器人模型格式，可以描述关节、质量、惯量、碰撞、传感器、执行器和地面。

### MuJoCo
模拟机器人运动、碰撞、摩擦和动力学的物理仿真引擎。

### mjlab
围绕 MuJoCo 的机器人强化学习实验工具链，用于环境、训练任务、并行仿真、日志和策略导出。

### BAM
用于辨识机器人执行器和动力学参数的一类工具/方法。可帮助估计延迟、摩擦、力矩响应等，让仿真更接近实机。

### 域随机化（Domain Randomization）
训练时随机改变仿真参数，让策略适应更多现实情况。可以随机质量、摩擦、延迟、噪声、电机强度和地面条件。

### Sim2Real
Simulation to Reality，把仿真中训练的策略迁移到真实机器人上。

### Sim-to-Real Gap（仿真到现实的差距）
仿真和真机之间的差异，常见来源包括打印公差、结构柔性、齿轮间隙、舵机延迟、传感器噪声、电池压降和地面摩擦。

## 五、调试与验收

### Bring-up
把新硬件从“完全不能运行”逐步调到“能启动、能通信、能执行基本动作”。推荐顺序：主控启动 → 串口 → 单舵机 → 全总线 → IMU → 站姿 → 策略。

### 台架测试
把机器人固定在桌面、支架或安全绳上测试，避免第一次动作时直接摔落或撞击。

### 急停（E-stop）
危险时立刻停止电机或切断动力的机制。最好同时有软件急停和物理断电方案。

### CRC / 校验和
通信数据包中用于检查数据是否传输错误的附加值。错误可能来自线缆、波特率、供电、信号方向或总线干扰。

### 日志（Log）
软件运行过程保存的状态和错误记录。建议记录控制周期、丢帧、舵机温度、电压、总线错误、IMU 数据和策略版本。

### Commit
Git 仓库中的一次确定代码版本记录。复现时应保存 commit，确保以后能找到同一版本。

### Release
项目作者发布的稳定版本或文件包，可能包含 CAD 源文件、STL、装配说明和 BOM。

### License（许可证）
规定代码、模型、图纸和文档能否使用、修改、再发布或商用的法律条款。代码许可证不一定自动适用于 3D 模型和图纸。

## 七、建议阅读顺序

1. 先看 **BOM、CAD、舵机、主控、HAT、IMU**，理解机器人由什么组成。
2. 再看 **总线、UART、半双工、ID、零位、50 Hz、robotd**，理解机器人怎样被控制。
3. 再看 **MJCF、MuJoCo、Observation、Action、Policy、ONNX**，理解仿真和策略怎样连接真机。
4. 最后看 **BAM、域随机化、Sim2Real、Reward、PPO**，理解为什么需要重新训练和参数辨识。

> **最简记忆：BOM 决定买什么，CAD 决定怎么装，IMU 告诉机器人姿态，舵机负责运动，HAT 负责连接，robotd 负责实时控制，MJCF/MuJoCo 负责仿真，Policy/ONNX 负责决策，Sim2Real 负责把仿真策略带到真机。**
