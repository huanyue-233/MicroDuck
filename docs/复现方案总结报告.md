# Microduck 复现方案总结报告

> **资料截止：2026-09-24**  
> **定位：** 面向“从零做出一台可站立、可运行控制策略的 Microduck 类双足鸭机器人”的调研与实施报告。本文综合官方仓库、第三方复刻仓库、CAD/硬件资料、仿真与 RL 训练资料，以及公开社区构建记录。仓库和模型仍在持续更新，正式采购前应把本文中的分支、Release 或 commit 冻结下来。

---

## 1. 执行摘要

### 1.1 最重要的结论

1. **Microduck 不是一个单仓库项目，而是“机械模型 + 电控硬件 + 主控运行时 + RL 训练 + ONNX 策略”五层系统。** 只下载一个 GitHub 仓库无法完成复现。
2. **官方软件已经足够成熟，但官方机械硬件并非完整开源硬件。** 官方 `microduck` 主要是 Rust 运行时和守护进程；`microduck_rl` 公开 MJCF、STL、仿真与训练方法；官方 `elec_RPI_Robot_HAT` 公开了 HAT 的 KiCad 工程。`imu_to_dxl`、完整可编辑机械 CAD、生产 BOM 与装配文档仍主要依赖社区逆向。
3. **复现应优先采用“HD-1910 国产舵机 + Radxa Zero 3W + 官方/社区 HAT + 社区 IMU 转接板”的路线。** 这条路线的原因不是它与原机完全一致，而是采购、结构改件、调试工具和实际装机记录相对完整。
4. **不要指望官方 XL330 策略直接适配 HD-1910。** 舵机质量、尺寸、力矩、回差、减速与控制协议不同；换执行器至少要重新做关节标定、BAM/执行器参数辨识、质量/质心修正，并重新训练或进行充分的策略适配。
5. **先做桌面调试，再做整机集成。** 先在外部电源、URT2/USB 调试板和裸 Radxa 上完成：舵机 ID、总线通信、零位、方向、站姿、IMU 读取、策略推理；之后再把 HAT、电池和线束塞进机身。
6. **第一阶段目标不要定成“会走路”，而应定成可验收的里程碑：** 15 个舵机稳定在线、IMU 可同步读取、站姿可重复、急停和限位可靠、控制环稳定在 50 Hz，最后再进入 sim2real。

### 1.2 推荐的复现路线

```text
官方 microduck_rl / 官方模拟器
        ↓ 先验证 MJCF、观测 61 维、动作 14 维、ONNX 推理
社区 CAD / OpenMicroDuck HD-1910 结构
        ↓ 打印、模块装配、机械干涉修正
HD-1910 × 15 + URT2 + 外部电源
        ↓ 舵机 ID / 协议 / 零位 / 站姿 / 总线时序
Radxa Zero 3W + HAT + IMU 转接板
        ↓ 50 Hz 控制环、串口、IMU、摄像头、系统镜像
HD-1910 专用仿真参数与策略
        ↓ 执行器辨识、域随机化、训练、导出 ONNX
整机走路 / 恢复 / 拾取 / 坐站
```

## 2. Microduck 系统拆解

### 2.1 目标硬件形态

官方仓库将 Microduck 描述为约 **25 cm、约 800 g** 的双足机器人，由运行在 Rockchip RK3566 上的控制系统驱动，核心控制循环为 **50 Hz**，机械上使用 **15 个舵机**，其中运动策略通常控制 14 个关节，另一个舵机用于嘴部/下颚机构。官方公开资料通常给出约 25 cm、约 800 g；社区逆向模型记录约 737 g，当前公开商店/资料的口径并不完全一致，具体质量会随舵机、电池、打印材料和结构改件变化。

建议把目标拆成以下层级：

| 层级 | 目标 | 是否必须首版完成 |
|---|---|---:|
| 机械 | 15 个舵机能够装入、无干涉、脚底可稳定支撑 | 是 |
| 电气 | 舵机总线、IMU、主控、电源、急停/断电 | 是 |
| 主控 | Radxa 启动、串口、ONNX Runtime、日志 | 是 |
| 控制 | 站姿、坐姿、关节限位、IMU 闭环 | 是 |
| 策略 | 在仿真中复现官方动作，并可导出 ONNX | 是 |
| 传感 | 摄像头、ToF、音频、WebRTC | 可后置 |
| 高级行为 | 行走、跌倒恢复、拾取、踢球、滚动 | 分阶段 |

### 2.2 软件和数据流

官方软件仓库的核心组织方式是多个 Rust daemon 通过 Unix socket 分工：

- `robotd`：唯一直接拥有电机总线和 50 Hz 控制环的服务。
- `configd`：网络、设备名、配对和系统配置。
- `updaterd`：更新验证、原子切换、健康门控和回滚。
- `btd` / `padd`：蓝牙、手柄和输入通道。
- `mediad`：摄像头、音频、编码和 WebRTC。
- `tof` 等传感器服务：独立拥有传感器，避免传感器故障拖垮运动控制。
- `robotctl` / `duckctl`：本地或蓝牙操作入口。

官方 RL 仓库的策略接口是 **61 维 observation → 14 维动作**，训练与部署频率为 50 Hz。社区模拟器也按这个接口运行，适合在没有硬件时先验证 ONNX 和行为切换。

### 3.3 社区内容与实物进展

- `microduck-replica` 的 README 记录：HD-1910 整机于 **2026-09-13** 装出，**2026-09-18** 已完成 15 颗舵机上总线并能站起/坐下；其一次台架同步读取记录为 15 颗在线、0 超时、0 校验错、约 4.8 ms。零位、方向、站姿和策略仍在持续校准。这是很有价值的实物里程碑，但不等于已经完成稳定行走。
- `OpenMicroDuck` 的公开说明采用“两阶段 BOM”：先做桌面调试版，把主控和舵机驱动板放在体外，使用适配器和显示器调试；待 HAT 与 IMU 板完成后再整机集成。
- 公开 Bilibili、技术博客和社区文章大多能提供采购、打印、国产舵机或部署经验，但视频中的“已调通”“低成本”必须区分为演示、站立、基本动作还是完整行走，不能直接视为可复验的工程结论。
- 社区资料中经常出现“官方硬件完全不开源”的旧说法。较新的核对结果显示，官方 `elec_RPI_Robot_HAT` 已公开；但 `imu_to_dxl`、完整生产级机械 CAD 和装配 BOM 仍不能按官方开源硬件看待。
- 建议给每条资料打证据标签：**官方产品规格、官方源码/模型、实物测量、社区重建/推断、假设**。例如 61→14、15 舵机、50 Hz 属于官方源码/运行时证据；M2 螺丝数量、轴承型号、打印件配合和 `F550` 包络尺寸属于社区重建或实测，不应写成官方生产参数。

## 4. 复现路线比较

### 4.1 路线 A：官方 XL330 等价复刻

**配置：**

- Dynamixel XL330-M288-T ×15。
- 官方公开 STL/MJCF 与官方运行时。
- 官方 `elec_RPI_Robot_HAT`。
- 社区重建的 `imu_to_dxl` 或自制等价板。
- Radxa Zero 3W/RK3566。

**优点：**

- 与官方 MJCF、BAM 参数、寄存器和运行时最接近。
- 最有希望直接运行官方 ONNX 策略。
- 软件改动最少，适合研究官方栈、控制环、策略加载和 WebRTC。

**缺点：**

- 舵机成本高，且不同地区价格差异大。
- 官方没有完整可编辑机械 CAD 和生产 BOM，直接打印仿真 STL 可能遇到配合、公差、螺纹孔和走线问题。
- `imu_to_dxl` 仍需自制或采用社区重建。

**适合：** 预算充足、目标是最大限度复现官方行为、愿意承担机械逆向工作的人。

### 4.2 路线 B：社区 HD-1910 复刻

**配置：**

- 飞特 HD-1910-C001 ×15。
- `microduck-replica-cad` 的 HD-1910 v2.0 或其改进版本。
- `microduck-replica` 的 BOM、总线与调试文档。
- Radxa Zero 3W 2 GB。
- 官方 HAT + 社区 `imu_to_dxl`。
- 官方运行时的 HD-1910 协议适配分支/自写 `FeetechIo`。
- HD-1910 专用执行器模型和策略。

**优点：**

- 采购价格和供货通常更友好。
- 结构件已有针对舵盘凸起、安装干涉和 3D 打印强度的改件。
- 有较完整的中文 BOM、调试记录、踩坑记录和实物进展。
- 官方运行时的总线访问已经抽象在接口后，理论上不需要重写控制环、策略、IPC 和安全层。

**缺点：**

- 不是“换一颗舵机”这么简单：协议、内存表、增益单位、舵机参数、质量、回差和动力学都不同。
- 官方 XL330 策略不可直接视为可用，必须重新校准和训练/适配。
- 社区 `imu_to_dxl` 首板、连接器、固件和整机实测仍可能变化。
- HD-1910 满电 8.4 V 已接近规格上限，电源设计不能照搬 XL330 的超压做法。

**适合：** 预算有限、重点是做出实体机、能够接受算法和电气适配工作的人。**这是本文推荐的首选路线。**

### 4.3 路线 C：OpenMicroDuck 优化结构路线

**配置：**

- OpenMicroDuck 优化后的结构件。
- HD-1910 或 HL-2909。
- OpenMicroDuck BOM、CAD 和结构说明。
- JoyandAI 的 HD-1910 RL fork。
- 官方 HAT 或兼容的 Zero HAT，外加 IMU 转接板。

**优点：**

- 对 3D 打印、舵盘凸起、头部干涉、脖子薄弱、躯干强度和脚踝装配做了针对性优化。
- 文档直接将“桌面调试”和“整机集成”分开，工程流程更合理。
- 对想做一个“完全公开自己的衍生版本”的团队更友好。

**缺点：**

- 与官方外形、MJCF 和社区主复刻的零件不一定一一兼容。
- 结构优化会改变质量、惯量、关节摩擦和重心，策略仍需相应调整。
- 对板卡、IMU 板和整机长期运行的公开实测数量少于成熟商业产品。

**适合：** 打算自己维护一套硬件、愿意接受结构优化和重新标定的人。

### 4.4 路线 D：参考 Open Duck Mini v2 的方法

Open Duck Mini v2 不是 Microduck 的同尺寸复刻，而是约 42 cm 的 BDX-inspired 双足机器人。它公开了 Onshape、BOM、打印指南、装配指南、Pi Zero 2W runtime、MuJoCo/Mujoco Playground/AWD 和 BAM 执行器识别资料。

它的价值在于提供一套可借鉴的方法论：

1. 在 CAD 中建立参数化机构。
2. 导出 URDF/MJCF。
3. 使用 BAM 对执行器和摩擦建模。
4. 在仿真中训练步态。
5. 在树莓派级别主控上运行策略。
6. 用 sim2real 日志迭代质量、摩擦、延迟、控制增益和动作缩放。

不要直接把 Open Duck Mini 的零件、关节尺寸、策略或 BOM 拿来替换 Microduck。

### 4.5 综合评分

| 维度 | 官方 XL330 | 社区 HD-1910 | OpenMicroDuck | Open Duck Mini v2 |
|---|---:|---:|---:|---:|
| 与官方运动学一致性 | 5 | 4 | 3~4 | 1 |
| 采购可行性 | 2~3 | 4 | 4 | 4 |
| 机械可打印性 | 2~3 | 4 | 4~5 | 4 |
| 官方策略可复用性 | 5 | 1~2 | 1~2 | 1 |
| 中文资料完整度 | 3 | 5 | 4 | 2~3 |
| 实物验证公开程度 | 2~3 | 4 | 2~3 | 4 |
| 适合第一次复现 | 3 | **5** | 4 | 2 |
| 适合研究官方栈 | **5** | 3 | 3 | 2 |

评分含义：5 为相对最优，不代表项目已经产品化或所有功能已被独立第三方重复验证。

## 5. 推荐实施方案：HD-1910 社区复刻 + 官方软件栈

### 5.1 固定一条“基线”，不要混用未验证零件

建议首版固定为：

- 机械基线：`microduck-replica-cad` HD-1910 v2.0，或 OpenMicroDuck 结构二选一。
- 舵机：HD-1910-C001 ×15；不要在中途混用 XL330、HL-2909、STS3215。
- 主控：Radxa Zero 3W 2 GB，优先使用有明确启动记录的批次。
- 系统：以社区已验证的 Armbian/Radxa 启动组合为准，不要默认任何 Zero 3W 板卡都能使用同一镜像。
- 总线：单线半双工 TTL，1 Mbps，明确 UART、收发方向和供电路径。
- IMU：优先使用社区 `imu_to_dxl` 设计，使 IMU 以总线设备形式参与同步读取；桌面阶段可先使用独立 I2C/SPI IMU。
- 策略：先跑仿真和动作序列，不直接把官方 XL330 walking ONNX 送到 HD-1910 真机。

### 5.2 阶段 0：资料、版本和合规冻结

建立自己的 `repro-lock.md`，至少记录：

```text
pollen-robotics/microduck       branch/tag/commit
pollen-robotics/microduck_rl   branch/tag/commit
pollen-robotics/elec_RPI_Robot_HAT  commit
fanhao375/microduck-replica     commit
fanhao375/microduck-replica-cad Release
JoyandAI/OpenMicroDuck          commit
JoyandAI/microduck_rl           branch/commit
Radxa Zero 3W 板卡批次与存储介质
舵机型号、固件版本、出厂 ID、校准日期
```

同时把 BOM 拆成三类：

1. **必须量产件：** 15 舵机、主控、HAT/转接板、IMU、摄像头、电池、打印件、轴承和紧固件。
2. **桌面调试件：** URT2、7.5 V/3 A 以上限流电源、PD 电源、USB 线、MicroHDMI、串口/逻辑分析工具。
3. **替代/后置件：** ToF、音频、麦克风、扬声器、NPU、无线手柄、电池管理和外壳细节。

### 5.3 阶段 1：先在仿真和浏览器中跑通

官方 RL 仓库给出的基本流程如下，命令仅作结构示例，实际参数以锁定的版本为准：

```bash
git clone https://github.com/pollen-robotics/microduck_rl
cd microduck_rl
uv sync

# 需要 CUDA GPU；先用较小环境数量验证安装
uv run train Mjlab-Velocity-Flat-MicroDuck --env.scene.num-envs 4096

# 播放训练结果
uv run play Mjlab-Velocity-Flat-MicroDuck \
  --wandb-run-path <entity/project/run_id>

# 导出 ONNX
uv run scripts/export.py Mjlab-Velocity-Flat-MicroDuck \
  --wandb-run-path <run>

# CPU MuJoCo 下先验证推理、观测和动作维度
uv run scripts/infer_policy.py --walking output.onnx
```

没有 CUDA 时，可以先使用官方网页模拟器或 Hugging Face Jobs。仿真阶段至少要记录：

- observation 的 61 维顺序和归一化方式。
- action 的 14 维顺序、缩放和默认关节角。
- 控制频率、推理耗时、动作延迟和命令格式。
- 关节方向、零位、行程、质量、惯量、脚底接触和地面摩擦。
- BAM 参数、输入电压、压降、摩擦和回差随机化范围。

### 5.4 阶段 2：机械件和执行器准备

**打印与装配：**

1. 下载与舵机型号匹配的版本；不要把 XL330 版结构件和 HD-1910 版舵盘安装位混用。
2. 首次不要打印整机全部外壳。先打印左腿、右腿、头颈和躯干的关键配合件。
3. 每个舵机先单独安装测试，检查输出轴、舵盘方向、螺丝孔和线材弯曲半径。
4. 对 8 个受舵盘凸凹差异影响的配合件重点检查：上腿、腿、小腿、躯干底座、yaw-to-roll、轴承座、加固板和头部运动件。
5. PLA 用于快速原型，承力件可评估 PETG、尼龙或 CNC 加强件；脚垫优先考虑 TPU。
6. 装配时记录每个零件的实际质量和修改内容，后续覆盖 MJCF 的质量/惯量。

**机械验收：**

- 断电手动转动每个自由度，无明显卡滞。
- 装上舵机但不通电时，关节能走完整安全行程。
- 脚底落地时左右脚接触面一致，机器人重心投影可落在支撑多边形内。
- 头部和喙动作不干涉壳体。
- 线束不进入舵盘、轴承或折叠夹点。
- 站立姿态下无结构件持续受压或打印层剥离。

### 5.5 阶段 3：桌面电气调试

推荐顺序：

1. 只接一颗舵机，用限流电源确认电压、极性、信号和温升。
2. 给每颗舵机设置唯一 ID，记录“物理关节 ↔ ID ↔ 左右方向 ↔ 软件关节名”。
3. 使用 URT2 或等价 USB 总线工具，逐颗 ping、读位置、读电压、读温度、读负载。
4. 将 15 颗舵机接入总线，低速测试广播/同步读取，确认没有重复 ID、总线反射、线序错误或供电压降。
5. 用网页调试台或最小 Python/Rust 工具，完成单关节位置控制和动作序列。
6. 再接入 Radxa，只让主控读取状态，不立即启用策略。
7. 先固定在支架上做站姿和坐姿，不要手持悬空测试高增益闭环。

**HD-1910 特别注意：**

- 舵机线接口与 FE-URT-2/URT2 的接口规格可能不同，需要专用转接线或临时飞线。
- 先确认信号、VCC、GND，再接外部舵机电源；任何 USB 与外部电源并联都要先确认不会反灌。
- 总线供电线不能通过小型传感器板承载全部舵机电流，应采用合理的电源分配和公共地。
- 记录每颗舵机固件版本与寄存器默认值，避免不同批次默认增益或回传行为不同。

### 5.6 阶段 4：主控和系统 bring-up

建议主控使用 Radxa Zero 3W 2 GB。社区逆向和官方运行时资料指出，关键点包括：

- 舵机串口通常映射到 `/dev/ttyS2`，需要确认设备树和板卡批次。
- Armbian 默认的 `serial-getty@ttyS2` 可能占用舵机串口，应先检查并停用。
- 某些 Zero 3W 批次需要匹配的引导程序、DTB 和内核组合；不要只换一张 SD 卡就认定主控损坏。
- 若启用 RK3566 NPU，需要相应 overlay、驱动和 RKNN runtime；NPU 不是第一阶段运动控制的必要条件。
- 使用硬件 I2C 时需检查引脚复用与 USB-C PD/电源协商的取舍。
- 先让系统在不接电机的情况下稳定启动、联网、SSH、日志记录和版本报告。

建议在系统层建立如下检查脚本：

```bash
uname -a
cat /etc/os-release
ls -l /dev/ttyS2
fuser -v /dev/ttyS2
ip addr
python3 -c "import onnxruntime as ort; print(ort.get_available_providers())"
```

然后再编译/部署官方 runtime 或 HD-1910 适配分支。官方贡献指南支持在 Linux/macOS 上运行 workspace 测试；硬件部署应另外记录目标板架构、交叉编译和 ONNX runtime 安装差异。

### 5.7 阶段 5：运行时适配

对于 HD-1910，优先采用“保留控制框架，只替换总线适配层”的策略：

```text
robotd / 50 Hz loop
        ↓
duck-control / RobotIo trait
        ↓
FeetechIo（STS/SMS 协议、寄存器、位置/速度/电压/温度）
        ↓
HD-1910 总线
```

需要逐项确认：

- 协议帧格式、校验和、波特率、回传延迟。
- 位置单位和角度方向。
- 位置、速度、负载、电压、温度的寄存器地址与字节宽度。
- 位置目标、速度限制、扭矩开关、EEPROM 写入和重启命令。
- PID/增益单位与官方 Dynamixel 表示方式的差异。
- 舵机故障、超温、欠压、掉线时的安全行为。
- `imu_to_dxl` 是使用 Dynamixel 协议模拟 IMU，还是由主控走 I2C/SPI 直接读取。

完成单关节控制后，再实现：

1. 读 15 舵机 + IMU 的同步状态。
2. 50 Hz 控制环计时与丢帧统计。
3. 观测构造、归一化和动作缩放。
4. 限位、回退姿态、跌倒保护。
5. ONNX 加载失败时保留旧策略或进入安全站姿。

### 5.8 阶段 6：HD-1910 仿真参数与策略训练

必须建立一份“真实硬件参数表”，不要只把 XL330 的参数改成 HD-1910 的额定力矩。至少包括：

- 单舵机质量和惯量。
- 舵机外形导致的安装偏移。
- 减速比、死区、回差、摩擦、速度上限。
- 输入电压、负载下压降和热保护行为。
- 实际位置跟踪误差、延迟和控制周期抖动。
- 关节零位和正负方向。
- 打印件质量、脚底摩擦、结构柔性和螺丝预紧力。
- 电池、HAT、线束和 IMU 的实际位置。

建议按以下顺序训练：

1. **站立保持**：只训练站姿、重心和 IMU 稳定。
2. **坐站切换**：验证关节限位和动作平滑度。
3. **原地小步**：低速度、平地、无复杂动作。
4. **速度跟踪**：加入前后/左右/偏航命令。
5. **跌倒恢复**：单独训练脸朝上、脸朝下、坐姿恢复。
6. **拾取、踢球、滚动**：这些动作对质量、脚底接触和延迟更敏感。

每轮训练都应保留：checkpoint、仿真参数、随机种子、MJCF、ONNX、观测日志和真机回放。导出前检查 ONNX 输入输出形状、归一化是否已融合、默认关节角和动作缩放是否写入元数据。

### 5.9 阶段 7：整机集成与行为验收

整机集成顺序建议：

1. 先固定或吊装在安全支架上。
2. 连接电池、主控、HAT、IMU、总线和摄像头。
3. 验证上电浪涌、待机电流、空载电流、站姿峰值电流和电池压降。
4. 验证单次启动后 15 舵机和 IMU 都能被发现。
5. 运行站姿策略，限制动作幅度和速度。
6. 运行坐站、轻推恢复，再运行低速直行。
7. 最后才允许自由行走、踢球、拾取和滚动。

## 7. 安全、可靠性与调试原则

### 7.1 电气安全

- 第一次上电使用限流电源，先测空载，再测单舵机，再测全总线。
- 外部电源、USB、主控 5 V 和舵机电源之间避免反向供电。
- 所有模块必须共地，但动力电流不能经由细小信号线或 IMU 板回流。
- 舵机电源线尽量采用星形/分支供电，避免所有电流穿过单个小型连接器。
- 电池必须有合适的保护、保险和低压策略；不能仅凭“额定 7.4 V”判断系统安全。
- 总线信号应先以示波器/逻辑分析仪确认电平和方向，再接入昂贵主控。

### 7.2 机械安全

- 初次运行必须有吊架、透明防护罩或低位安全绳。
- 策略调试时把动作速度、位置范围和扭矩限制设为保守值。
- 让机器人站在软垫上，但不要让脚底陷入会改变摩擦的厚软材料。
- 手不要放在舵盘、膝关节、脚踝和喙的夹点附近。
- 所有策略切换、模型加载和异常回退都要先回安全姿态。

### 7.3 软件安全

- 运行第三方 ONNX 前检查输入输出形状、模型来源、manifest 和观测契约。
- 策略文件不应绕过关节限位、速度限位和掉线保护。
- 不要把更新、网络、视频、策略下载和电机控制放进同一个高权限进程。
- 保留可回退的已知良好策略和可断电恢复的系统镜像。
- 把“仿真成功”“台架站立”“真机行走”分别记录，不要合并为一个“已完成”。

## 8. 分阶段验收标准

### A. 仿真验收

- [ ] MJCF 能加载，关节数、质量、惯量和坐标系无异常。
- [ ] 观测形状为 61，动作形状为 14。
- [ ] 站立、坐站、行走至少各有一段可回放视频/日志。
- [ ] ONNX 导出后 CPU 推理结果与训练框架一致。
- [ ] 记录控制周期、推理耗时和动作延迟。

### B. 单舵机和总线验收

- [ ] 15 颗舵机 ID 唯一且有物理标签。
- [ ] 单颗读写、位置、温度、电压、负载可用。
- [ ] 全总线连续运行 10 分钟无超时/CRC 错误或有可解释的错误率。
- [ ] 同步读取周期满足 50 Hz 控制环预算。
- [ ] 电源电流和电压压降已记录。

### C. 机械验收

- [ ] 全部自由度手动无卡滞。
- [ ] 关节零位和软件方向一致。
- [ ] 站姿左右对称或差异已记录。
- [ ] 每个结构改件有版本号和 STL/STEP/SolidWorks 来源。
- [ ] 脚底接触和重心投影稳定。

### D. 主控验收

- [ ] Radxa 能可靠冷启动、重启和 SSH 登录。
- [ ] `/dev/ttyS2` 未被登录控制台占用。
- [ ] 50 Hz 控制环丢帧统计在目标范围内。
- [ ] ONNX Runtime 在 ARM 上可稳定推理。
- [ ] 日志、温度、总线、电池和策略状态可查询。

### E. 真机行为验收

- [ ] 站姿保持 60 秒以上。
- [ ] 坐下/站起连续执行 10 次无明显漂移。
- [ ] 轻推后能安全回稳或进入安全姿态。
- [ ] 低速前进/后退/转向能在安全绳下重复。
- [ ] 失败时可急停，且不会因为策略异常继续发出危险动作。

## 9. 主要风险与应对

| 风险 | 影响 | 预防/应对 |
|---|---|---|
| 版本快速变化 | 文档、分支、接口不一致 | 冻结 commit/Release，保存可复现环境 |
| 仿真 STL 直接打印失败 | 装不起来、干涉、断裂 | 采用 HD-1910 优化 CAD；先打印关键模块 |
| 执行器替换后策略失效 | 站不住、抖动、发热 | 重新辨识执行器和质量，先站姿再行走 |
| 舵机 ID/方向错误 | 机械损坏 | 单颗标定、物理标签、低速限位 |
| 电源压降/反灌 | 掉线、重启、损坏 | 独立动力供电、限流、共地、严禁盲目并电 |
| 串口被系统占用 | 总线无响应 | 检查 `fuser`、停用 serial-getty |
| IMU 时间/坐标不一致 | 行走漂移、策略发散 | 统一坐标系、时间戳和 50 Hz 同步读取 |
| 结构版本混用 | 孔位、舵盘和质量不一致 | 为整机建立唯一机械基线 |
| 第三方策略不安全 | 失控或撞击 | 支架运行、模型检查、限位和回滚 |
| 许可证误用 | 无法发布/商用 | 软件、模型、图纸分别核对许可证 |

## 10. 许可证与发布注意事项

这是复现项目很容易忽略、但实际发布时必须处理的部分：

- 官方 `microduck` 运行时和官方 HAT 仓库为 Apache-2.0，可按许可证要求保留版权、NOTICE 和修改说明。
- `microduck_rl` 中代码与 3D 模型的许可证边界需要分别查看；模型资产不能简单按照代码许可证处理。
- `microduck-replica` 明确将原创脚本/工具与上游 3D 模型衍生的图纸、装配图分开授权；其文档和派生结构通常带 CC BY-NC-SA 4.0 约束。
- `OpenMicroDuck` 的软件与硬件/图纸同样存在分层许可证，仓库 `NOTICE.md` 明确说明其与 Pollen Robotics 无隶属、未获官方背书。
- 公开发布时应：
  1. 保留上游作者、许可证和来源链接。
  2. 不把社区逆向 BOM 宣称为官方生产 BOM。
  3. 不使用 Pollen Robotics 商标或“官方认证”表述。
  4. 商业化前逐项确认 MJCF/STL/图纸/代码/舵机资料的再分发许可。
  5. 在仓库中写清楚哪些是直接上游文件、哪些是转换产物、哪些是原创改件。

## 11. 最终建议

### 11.1 如果目标是“尽快做出实体”

选择：

```text
microduck-replica-cad HD-1910 v2.0
+ microduck-replica BOM/调试记录/踩坑记录
+ HD-1910 ×15
+ Radxa Zero 3W 2GB
+ 外置 URT2 + 限流电源
+ 官方 RPI Robot HAT
+ 社区 imu_to_dxl
+ 先站姿/坐站，再重训行走策略
```

这是当前资料完整度、实物验证度和采购可行性之间最平衡的方案。

### 11.2 如果目标是“最大限度复现官方行为”

选择 XL330 路线：

```text
官方 microduck + microduck_rl
+ XL330 ×15
+ 官方 RPI Robot HAT
+ 社区 imu_to_dxl
+ Radxa Zero 3W
+ 官方 ONNX 策略
```

但是应接受更高成本、更长机械准备周期，以及官方没有完整生产 CAD/BOM 的现实。

### 11.3 如果目标是“建立自己的开源机器人平台”

选择 OpenMicroDuck 作为结构与文档起点，但要自己维护：

- 参数化 CAD 和版本策略。
- 结构件材料、打印方向与配合公差。
- HD-1910 真实质量/惯量/回差数据。
- HAT、IMU、主控和电池的线束标准。
- 仿真模型、训练配置、ONNX 发布和真机回放数据。

### 11.4 不推荐的做法

- 直接下载 47 个仿真 STL、整机一次性打印，然后期待能装配。
- 用 HD-1910 机械装机后直接加载 XL330 的行走 ONNX。
- 在未确认接口和供电之前把 USB、URT2、电池和 HAT 同时接上。
- 把 Open Duck Mini v2 的策略或零件直接移植到 Microduck。
- 只依据视频标题判断“已复现成功”。
- 只保存最终代码，不保存舵机固件、机械版本、电源配置和训练参数。
